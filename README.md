# free-ai-gateway

[English](README.en.md) · 简体中文

为个人使用各种模型 API 建立的 OpenAI 兼容聚合网关，目前主打**免费 API 的聚合调用**。使用自己的 Mac 本机或 VPS 和 Provider 账号，把不同服务商统一到一个 `/v1` 地址。

## v1.2：双端 Provider 与用量

Mac 与 VPS 可以同时使用。在 App 的 Provider 页选择「同步到 Mac」或「同步到 VPS」，勾选服务商、预览目标变更后确认。两端都需升级到 v1.2，Mac 须先初始化，VPS 须有可用的 SSH 连接。同步包含已选 Provider 的配置、免费模型列表、密钥及日额度 / RPM 设置；目标同名配置会被覆盖。调用链、评分、日志和客户端密钥保持各自独立。

Provider 密钥经原生 SSH 通道传递，不进入 App 网页界面，不提供显示、复制或导出入口；预览中的临时数据会在取消、使用或5分钟后清除。目标使用私有权限文件保存。拥有本机或服务器管理员权限的人仍能读取底层配置，这不是对设备所有者的密钥托管隔离。

概览页的「汇总 VPS + Mac」按需读取同一 UTC 日及最近60秒的双端快照，显示两端与合计；重复点击仅刷新，不回写计数。同地址、同密钥归为一组；不同密钥分开显示，但可能仍共享上游账号额度，额度上限不会相加。

统计包括实际生成 POST 的失败、重试、降级和模型测试；目录查询 GET 不计入。token 仅统计上游已提供的用量。升级前缺少的数据、不可达实例和记录缺口会标注不完整，不能据此推算上游剩余额度。账本使用内置 SQLite，保留31天日汇总及有上限的近期请求，无新数据库服务。

**手动汇总不是全局限流器。** 两端同时调用仍可能触发共享账号的 RPM 或日额度；网关外调用不可见。请在两端合理分配额度并遵守上游限制。

## v1.1：Mac 本机与 Agent

App 可在「连接」中切换 Mac 本机 / VPS。首次使用本机模式，初始化并保存首次显示的客户端密钥，启动网关，再添加 Provider、测试模型并配置 `agent` 或 `code` 调用链。原有 VPS 连接、配置和密钥独立保留，不会自动复制到本机。

本机组件随 App 提供，不需要另装 Python、Docker 或数据库服务。它只转发 API，不在 Mac 上加载模型；默认地址为 `http://127.0.0.1:18473/v1`，仅限本机访问。启动后可退出 App；在 App 中点击停止会关闭网关。重启或重新登录后需再次手动启动。默认最多 8 个 HTTP 连接，空闲连接 30 秒关闭，日志沿用有上限的本地存储。VPS 不安装 Mac 运行组件，也不新增依赖。

- **OpenClaw**：自定义 Provider 使用 `api: "openai-completions"`，Base URL 填本机地址，model 选择网关任务别名 `agent`。支持流式回复及客户端工具的多轮调用。
- **Codex**：自定义 Provider 使用 `wire_api = "responses"`，通过 `/v1/responses` 接入。支持完整历史、指令、普通函数工具、命名空间工具、文本自定义工具、SSE 和用量统计。工具实际执行仍由 Codex 负责。
- **兼容边界**：无服务端会话保存；使用 `store: false` 并发送完整历史。暂不支持 `previous_response_id`、后台任务、托管搜索、Responses 云端压缩、WebSocket、加密 reasoning 状态和自定义 grammar 工具，这些能力不会被伪装成成功。Claude Code 的 Anthropic Messages 接口暂不在支持范围内。

真实 OpenClaw 2026.9.1 和 Codex CLI 0.144.6 已通过隔离上游的写文件、读文件、工具结果回传和最终回复验证。这验证的是协议和工具流程；实际完成任务的质量、上下文长度及工具能力仍取决于你配置的上游模型。

Codex 配置示例（客户端密钥通过环境变量提供，保持自己的沙箱及审批设置）：

```toml
model = "agent"
model_provider = "personal_gateway"
web_search = "disabled"

[model_providers.personal_gateway]
name = "Personal Gateway"
base_url = "http://127.0.0.1:18473/v1"
env_key = "PERSONAL_GATEWAY_KEY"
wire_api = "responses"
supports_websockets = false
```

选择的上游模型必须支持工具调用。网关任务别名不会改变模型本身的能力或上下文上限。客户端发出的压缩、搜索或特殊工具请求如被拒绝，请关闭对应客户端能力；普通函数工具不受影响。

## v1.0

App 支持简体中文 / English 即时切换并记住选择。任务路由可分别设置手动顺序、评分排序，或首选优先（首个模型失败后对备用评分）；未单独设置的任务继承原默认策略。

调用日志可按请求编号查看同一次请求的模型选择与降级经过，包括候选得分构成、跳过原因、近期样本、首字等待和完整耗时；每页仍最多50条。得分是请求开始时的快照，实际结果以业务记录为准，旧日志无法补回未记录的说明。

可靠性评分使用最近24小时内、每个模型每个任务最近100个有效业务样本，采用平滑成功率。流式首个有效输出等待时间用于速度评分，完整回答耗时与输出速度单独显示；非流式和少量样本的速度分采用中性值。基础探测不改变业务评分，也不代表所有请求能力已恢复。

认证/权限异常会暂缓同一 Provider 并提示检查配置；限流或余额不足等待后再试；请求或模型不兼容只记业务失败，不触发通用模型禁用。空回复、断流、超时、网络错误和服务异常仍计入模型可靠性。Provider 暂缓跨重启保留，成功的手动模型测试可清除 Provider 暂缓；模型禁用仍由独立恢复探测处理。

## 能做什么

- App 内确认 SSH 主机指纹，使用密码、私钥或 ssh-agent 登录并部署网关。
- 新增 OpenAI 兼容 Provider，查询免费模型目录，测试可用性并加入任务链。
- 拖动模型调用顺序，或按能力分排序；可分别启用延迟与成功率加分。
- 调整不同任务的模型评分，内置默认分；升级保留个人配置。
- 空文本、空白、仅 reasoning 而无最终回答均按失败降级；合法工具调用有效。
- 普通请求和流式请求均支持降级。流式开始输出后若发生错误，会报告失败，不拼接其他模型的回答。
- 创建独立的客户端密钥，供 OpenAI SDK 或兼容客户端调用。

## 用 App 首次部署

VPS 需 root、Python 3，以及 apt / systemd 兼容的 Linux 环境。

1. 安装 App，下载并解压网关部署包。
2. 在 App「连接」中填写自己的服务器地址、SSH 用户和端口，选择登录方式。
3. 核对 App 显示的 SHA256 主机指纹并确认。密码仅保留在本次 App 会话；退出即清除。
4. 点击「继续首次部署」，在安装向导选择刚解压的网关目录，完成环境检查、部署与启动。
5. 填写自己的 Provider 密钥，保存向导生成的客户端密钥；完整值只显示一次。
6. 进入「调用说明」，复制自己的地址和调用示例。

已部署的网关可直接连接管理。SSH 端口留空时沿用系统 SSH 配置；加密私钥请先加载到 ssh-agent。首次指纹扫描需要能直接访问 SSH 端口。

## 新增 Provider 与免费模型

在「Provider」页新增服务商，填写名称、OpenAI 兼容 Base URL、密钥环境变量名和密钥。VPS 模式经 SSH 写入服务器；本机模式写入 App 私有实例目录。

在「扫描」页查询模型目录：查询只请求 `/models`，不发送生成请求。App 根据零价格元数据、已知免费模型标识或你明确登记的免费名单判断；任何非零价格证据优先于名单。计费未知时，先根据自己的账号套餐确认免费范围，再登记和测试。

测试可用后加入任务链。免费额度与模型目录由服务商决定，本项目不提供公共免费 API，也不承诺上游长期免费。

## 删除 Provider

App 和 VPS 更新至 v0.1.5 后，在「Provider」卡片点击「删除」，先查看受影响的调用链，再确认。删除会清理该服务商的模型引用、评分和配额设置，其余模型顺序保持不变。如果某条调用链会变空，请先在调用顺序中加入其他服务商的替代模型。

独立的实例密钥文件会在 VPS 私有备份后删除；共享、外部或含其他内容的密钥文件保留。历史调用日志与统计保留。运行中的网关会重启，健康检查失败则回滚。内置 Provider 删除后不会随重启重新出现；可以通过新增表单使用原 API 地址和密钥变量名重新添加。

## App 内单模型测试

v1.0.1 起，可从「模型」或「Provider」页打开单模型测试面板，选择服务商、选择或填写模型 ID、输入问题与输出上限，再点击开始。不会自动发出生成请求；每次测试会消耗上游额度，请先确认账号套餐和模型计费。

面板直接显示成功/失败、HTTP状态、完整回复或原始报错，并分别显示上游耗时和包含 SSH 往返的总等待时间；等待中实时计时。测试只调用所选模型一次，不自动降级，空回复仍视为失败。完整原始响应可展开查看，密钥隐藏；测试记录归入手动测试，不影响业务成功率或路由评分。中英文界面均可使用，模型返回内容保持原文。

## 按需查看模型日志

在 App 的「模型」页点击「调用日志」，可按时间范围、provider 或 provider/model 查询，三种方式都最多返回 50 条。时间范围可与 provider、模型、来源和失败筛选组合使用。修改筛选后点击查询，翻页替换当前结果，列表始终最多显示 50 条。模型行的「查看日志」可直接打开该模型。关闭窗口后不再拉取。

「业务成功率」只统计正常请求；手动测试的简短请求成功，不代表长对话、工具调用或流式请求也成功。日志显示耗时、HTTP 状态、安全原因码、输入规模和下一候选模型；降级前的失败不会再被最终成功掩盖。客户端主动停止单独标记，不计为模型失败。

App 与 VPS 更新至 v0.1.6 后，可点击「导出筛选范围全部日志」或某行的「导出本条」。导出保存到本机下载文件夹（JSONL），不受列表每页50条限制。每条包含完整请求正文、实际上游请求、完整响应、流式片段及原始报错；重试与降级过程保留。模型业务调用、手动测试、扫描测试和自动恢复均记录。Authorization、API key、Cookie 等凭据及已知密钥在写盘前隐藏，导出时再次处理。

完整内容仅从升级后实际记录；旧版本只有摘要，无法补回正文。日志保存在自己的 VPS，不会上传 GitHub。服务器最多保留最近50,000条记录，压缩详情累计超过512MiB时清理最旧整条记录（至少保留最新一条）；保留的正文不截断。导出采用固定数据库快照，成功后才生成最终文件并打开所在位置；文件仅当前本机用户可读写。

## 模型自动恢复

模型因多次失败被自动禁用后，网关会在 15 分钟后发送一个简短健康探测请求。失败后间隔延长到 30、60 分钟，之后每小时重试；时间进度在重启或跨天后保留。探测得到有效输出才会清除禁用和冷却，空文本或仅有思考内容仍算失败。

探测消耗 provider 配额，但不混入正常调用的成功率和延迟评分。额度不足时等待额度恢复。App 的模型页可查看下次探测时间；恢复不会改变你保存的模型顺序和评分策略。

## 调整顺序和评分

在「配置」页选择：

- **手动顺序**：按拖动后的顺序调用，跳过禁用、冷却或额度不足的候选。
- **评分排序**：使用能力分，可分别开启延迟与成功率加分；同分时保留拖动顺序。
- **首选优先**：先尝试列表第一个模型，不可用或失败后对备用模型评分。

每个任务可单独设置以上策略及加分开关，也可继承默认策略。

支持 `fast`、`balanced`、`thinking`、`code`、`writing`、`agent` 六种任务。保存配置后生效。新安装默认手动顺序，旧配置未包含排序策略时保留原有自动评分行为。

## 调用 API

把 `<VPS_IP>` 换成自己的地址，`GATEWAY_KEY` 使用自己的客户端密钥。

```bash
curl http://<VPS_IP>:8090/v1/chat/completions \
  -H "Authorization: Bearer $GATEWAY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"balanced","messages":[{"role":"user","content":"你好"}]}'
```

OpenAI SDK 的 `base_url` 设置为 `http://<VPS_IP>:8090/v1`，`model` 填上述任务名；添加 `stream: true` 可使用流式输出。也可使用 `tools/ask.py`：

```bash
python3 tools/ask.py --base http://<VPS_IP>:8090 "你好"
```

网关默认提供 HTTP。公网使用时应配置 HTTPS 反向代理；仅供自己使用也可以通过 SSH 隧道连接。管理功能只走 SSH，网关没有 HTTP 管理接口。

## 命令行安装

在自己的 VPS 解压部署包后执行：

```bash
sudo bash install.sh
# 在 App 中连接该服务器，完成 Provider 密钥配置与启动。
```

`install.sh` 默认安装到 `/opt/ai-gateway`，监听端口默认 8090；通过 `GATEWAY_DIR`、`GATEWAY_PORT`、`GATEWAY_HOST` 和 `SERVICE_NAME` 可指定安装参数。安装器不覆盖已有配置和默认评分文件，也不自动启动服务。
